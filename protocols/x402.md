# x402 — HTTP Payment Protocol

**Creator:** Coinbase (now x402 Foundation)
**Repo:** [github.com/x402-foundation/x402](https://github.com/x402-foundation/x402) (canonical; coinbase/x402 is now a dev fork)
**Version:** Protocol V2 (production SDKs: TypeScript v2.22.0, Go v2.22.0, Python v2.19.0; Java SDK added)
**License:** Apache 2.0
**Foundation:** x402 Foundation — GitHub org created 2026-04-01, Technical Charter dated 2026-03-31. TSC: Coinbase, Cloudflare, Stripe.

## What It Is

Settlement layer for per-request agent payments using HTTP 402 status code. An agent hits an API, gets a 402 response, signs a stablecoin authorization (EIP-3009 transferWithAuthorization), attaches it to the retry, and the payment settles on-chain. No accounts, no API keys, no invoices.

## Core Concepts

- **402 Response** — server returns payment requirements (amount, recipient, chain)
- **Facilitator** — verifies the payment permit and settles on-chain. Coinbase runs one, but anyone can run their own.
- **Schemes** — `exact`, `upto`, `batch-settlement` (multi-payment batching, all 3 SDKs), and `auth-capture` (two-phase hold/capture; spec + TS client)
- **Spend controls (SDK-level, TypeScript only)** — the TS client caps each payment (`maxAmountPerPayment`, default `"$1"`) and restricts which assets it will pay in (`allowedAssets`), checked before the payload is signed. Per-payment guardrail, not a running budget across payments. Not in the Python or Go SDKs.
- **Multi-chain** — Base, Ethereum, Polygon, Solana, Algorand, Aptos, Hedera, Stellar, Sui, Keeta, plus newer TON, NEAR, Cardano, Concordium and additional EVM chains (Arbitrum, MegaETH, Monad, Radius, ADI, HPP)
- **Upto scheme** — variable/max pricing (authorize up to X, settle actual usage). Shipped in TS and Go SDKs. Spec now covers both EVM (`scheme_upto_evm.md`) and SVM/Solana (`scheme_upto_svm.md`).

## What It Covers

- Per-request micropayments (agent pays per API call)
- On-chain settlement with gasless signing (EIP-3009)
- Facilitator architecture (verification + settlement)
- MCP transport (payment signaling in MCP tool calls)
- A2A transport
- Multi-chain support across EVM and non-EVM

## What It Doesn't Cover (Explicitly Out of Scope)

- Client-side budget management (still listed as out of scope in `specs/x402-specification-v2.md` on main, even though the TypeScript SDK ships per-payment spend controls)
- Agent delegation or mandates
- Cross-service spending coordination
- Subscription/recurring payments
- Fiat payment rails (crypto-only currently, fiat planned)

## Relationship to Other Protocols

- **Competes with MPP** at the settlement layer (stablecoin-only vs multi-rail)
- **Plugs into AP2** via the A2A x402 extension (crypto settlement for AP2 mandated purchases)
- **Independent of ACP/UCP** at the commerce layer

- **`spendControls` in the TypeScript client** ([PR #3124](https://github.com/x402-foundation/x402/pull/3124), merged 2026-08-13; docs [PR #3147](https://github.com/x402-foundation/x402/pull/3147), merged 2026-08-13) — per-payment USD cap (default `"$1"`) plus an asset allowlist, enforced before signing. TypeScript only; the feature matrix in `docs/sdk-features.md` marks Python and Go as not supported.
- **`upto` scheme on Solana** — SVM payment flow in the TS SDK ([PR #3094](https://github.com/x402-foundation/x402/pull/3094), merged 2026-08-12), spec `scheme_upto_svm.md` ([PR #3135](https://github.com/x402-foundation/x402/pull/3135), merged 2026-08-12), ComputeBudget instructions added ([PR #3155](https://github.com/x402-foundation/x402/pull/3155), merged 2026-08-14). `upto` was EVM-only before this.
- **SDK versions** — TypeScript and Go at v2.22.0, Python at v2.19.0 (up from v2.14.0 / v2.14.0 / v2.12.0 at the last check)
